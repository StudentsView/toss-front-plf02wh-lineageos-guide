# 토스 프론트 1.5세대 PLF02WH LineageOS 18.1 설치 가이드

**2026-10-27 설치 성공 사례.** 직접 진행한 작업 기록을 바탕으로, 여러 커뮤니티 글에 나뉘어 있던 절차를 한곳에 정리했다.

| 항목 | 내용 |
| --- | --- |
| 대상 기기 | 토스 프론트 1.5세대 `PLF02WH` |
| 설치 OS | LineageOS 18.1 |
| 사용 빌더 | [kyseong00/toss-front-lineageos-builder](https://github.com/kyseong00/toss-front-lineageos-builder) |
| 작업 환경 | Windows PC, Rockchip 드라이버, RKDevTool |
| 성공 기준 | LineageOS 부팅 및 초기 설정 진입 |
| 파일 제공 상태 | 펌웨어 이미지 7개, 드라이버, cfg 등은 준비 예정 |
| 적용 범위 | 이 기기에서의 성공 기록. 다른 모델과 보드 리비전의 동작은 검증하지 않았다. |

현재 저장소에는 문서와 라이선스만 있다. 설치에 필요한 파일은 추후 별도로 준비할 예정이다. 파일명, 버전, 체크섬과 파티션 대응표가 공개되기 전에는 이 문서만으로 플래싱을 진행하지 않는다.

## 1. 작업 전 확인

**플래싱과 `EraseLBA`는 데이터를 지우거나 기기를 부팅 불가능하게 만들 수 있다. 원본 백업을 검증한 뒤 진행한다.**

| 확인 항목 | 기준 |
| --- | --- |
| 모델 | 기기 라벨의 `PLF02WH` 확인. `PLF00WH`와 2세대에는 적용하지 않는다. |
| 백업 | 원본 이미지, 파티션 표, 설정 파일, 작업 로그를 별도 보관한다. |
| 주소 | 인터넷 예시나 다른 기기의 주소를 그대로 복사하지 않는다. |
| 개인정보 | 원본 펌웨어와 `userdata`에는 계정, 인증 정보, 기기 고유 정보가 포함될 수 있다. 공개 저장소에 올리지 않는다. |
| 전원 | 정격에 맞는 안정적인 전원을 사용한다. 쓰기 또는 삭제 중에는 케이블을 분리하지 않는다. |
| 하드웨어 | 쇼트 작업은 오접촉, 전원 레일 손상, 정전기 방전(ESD) 위험이 있다. 패드를 식별하지 못하면 중단한다. |

정상 부팅 확인은 결제 기능, 모든 주변 장치, 장기 안정성까지 검증했다는 뜻은 아니다. 이 문서는 제조사의 공식 설치 안내가 아니다.

## 2. 준비물과 파일

| 준비물 | 용도 및 상태 |
| --- | --- |
| 토스 프론트 1.5세대 `PLF02WH` | 설치 대상 |

| Micro USB 5핀 데이터 케이블 | 기기와 PC 연결. 충전 전용 케이블은 사용할 수 없다. |
| USB-C 전원 케이블과 전원 공급 장치 | 성공 기록에서는 25W 전원 장치를 사용했다. 케이블 자체의 와트 표기와 충전기의 총출력만으로 호환성을 판단하지 않는다. |

| 핀셋 등 작업 도구 | MaskROM 하드웨어 진입이 필요한 경우. 금속 도구로 주변 부품까지 접촉하지 않도록 주의한다. |

| --- | --- |
| 다운그레이드용 펌웨어 이미지 7개 | 준비 예정. 개별 파일명과 파티션 대응은 추후 명시한다. |
| Rockchip 드라이버 | 준비 예정 |
| RKDevTool | 준비 예정. 제공 버전과 메뉴 구성을 확인한다. |
| RK3399용 Loader | 준비 예정. 해당 기기와 작업에 맞는 파일을 확인한다. |
| `config.zip` 안의 `config_16.cfg` | 준비 예정. 기기의 실제 파티션 정보와 대조해야 한다. |
| 순정 `super.img` | 검증된 원본을 준비한다. 다운그레이드에 사용한 파일과 최초 상태의 원본 백업을 구분해 보관한다. |

| 백업용 rkDumper | 필요 시 원문 안내에 따라 별도 준비한다. 파티션 정보 확보와 실제 이미지 백업을 구분한다. |

SFF 설치 글은 RKDevTool v2.96, SUNMI 백업 글은 v3.37을 기준으로 한다. 메뉴 이름과 화면 구성이 다를 수 있으므로 서로 다른 버전의 화면을 그대로 섞어 적용하지 않는다. 이 성공 기록에서 사용한 도구의 정확한 버전과 파일 해시는 추후 보완한다.

## 3. 드라이버 설치와 연결 상태 확인

1. 기기를 PC에서 분리한 상태로 Rockchip 드라이버를 설치한다.
2. RKDevTool을 실행한다.
3. 기기의 USB-C 전원을 분리한 상태에서 하부 뚜껑을 연다. 1.5세대는 드라이버 같은 공구 없이 뚜껑만 열면 접점과 Micro USB 5핀 포트가 드러난다. Micro USB 데이터 케이블로 PC에 연결한다.
4. 초기화 버튼을 누른 채 USB-C 전원을 연결한다.
5. RKDevTool에 `Found One LOADER Device`가 표시되면 버튼을 놓는다. 화면이 검다는 이유만으로 성공으로 판단하지 않는다.

성공 사례에서는 순정 상태에서 Wi-Fi 연결 후 자동 업데이트가 진행된 뒤, 위 방법으로 Loader에 진입하지 못했다. 모든 기기에서 같은 조건으로 발생한다고 단정할 수는 없다. 5핀 케이블만 꽂아서는 작업 모드가 잡히지 않을 수 있다.

| 상태 | 다음 단계 |
| --- | --- |
| `LOADER` 인식 | 파티션 정보 확보와 백업을 진행한다. Loader가 이미 동작하면 하드웨어 쇼트를 추가로 할 필요는 없다. |
| 인식 없음 | 데이터 케이블, USB 포트, 드라이버, 전원 규격을 먼저 확인한다. |
| 초기화 또는 데이터 삭제 화면 | Loader 진입 성공이 아니다. 삭제를 실행하지 않고 중단한다. |
| 정상 연결 조건을 확인해도 Loader 진입 실패 | 아래 MaskROM 절차를 검토한다. |

## 4. MaskROM 진입이 필요한 경우

**토스 프론트 1.5세대 `PLF02WH`의 쇼트 대상은 `BOOT`와 `VCC_1V8` 접점이다.**

하부 뚜껑만 열면 두 접점과 Micro USB 5핀 포트에 접근할 수 있다. 나사를 푸는 드라이버나 추가 분해는 필요하지 않다. Windows용 Rockchip 드라이버 설치는 별도 준비 과정이다.

이름만 보고 패드 위치를 추측하면 안 된다. 원본 게시글의 해당 보드 실물 사진에서 두 패드의 표시와 주변 부품 배치를 확인하고, 본인 보드와 대조한다. 이 저장소에는 패드 위치를 검증할 사진을 제공하지 않는다. 사진에서 두 패드를 분명하게 식별할 수 없거나 보드 구성이 다르면 진행하지 않는다.

다른 세대나 다른 보드의 진입 방법을 혼용하지 않는다. 핀 이름이 비슷하다는 이유로 다른 단자를 대신 연결하지 않는다.

| 위험 | 주의 사항 |
| --- | --- |
| 전원 레일 손상 | `VCC_1V8`는 전원 레일이다. GND나 인접 패드와 오접촉하면 손상될 수 있다. |
| 전원이 남은 상태의 접촉 | 패드 식별과 도구 위치 확인은 전원을 분리한 상태에서 한다. Micro USB도 전원을 공급할 수 있으므로 모든 케이블을 분리해 확인한다. |
| 도구 미끄러짐 | 밝은 조명과 확대 도구로 확인하고 보드를 고정한다. 넓은 금속 면이 주변 부품에 닿지 않도록 한다. |
| ESD | 적절한 정전기 방지 작업 환경을 사용하고, 노출된 보드와 접점의 불필요한 접촉을 줄인다. |

패드와 연결 순서를 실물 사진으로 확인한 경우의 작업 기록은 다음과 같다.

1. 전원을 분리한 상태에서 확인한 두 패드와 주변의 간격을 다시 확인한다.
2. Micro USB 데이터 케이블을 PC와 연결한다. 이때도 보드에 전원이 들어올 수 있음을 유의한다.
3. 확인한 `BOOT`와 `VCC_1V8`만 일시적으로 연결한 상태에서 USB-C 전원을 연결한다.
4. RKDevTool에 `Found One MASKROM Device`가 표시되는지 확인한다. 화면에는 아무것도 표시되지 않을 수 있다.
5. 인식 후 쇼트 도구를 제거한다. 계속 쇼트한 채 백업하거나 플래싱하지 않는다.

인식 실패 시 전원이 들어온 보드 위에서 도구를 움직이며 다른 패드를 시도하지 않는다. 전원을 분리하고 접촉 위치부터 다시 확인한다.

## 5. Loader 적재와 원본 백업

**다운그레이드를 포함한 첫 쓰기 작업 전에 원본을 백업한다.**

1. MaskROM 상태에서 RKDevTool의 `Advanced Function` 탭을 연다. Loader 상태에서 소프트웨어 전환이 가능한 경우에는 [SUNMI 24번 글](https://gall.dcinside.com/mgallery/board/view/?id=sunmitechnology&no=24&page=1)의 `Go Maskrom` 절차를 확인한다.
2. `Boot` 파일 선택란에 검증된 RK3399용 Loader를 지정하고, 그 옆의 `Download`로 RAM에 적재한다. 전체 펌웨어 쓰기 버튼과 구분한다.
3. 로그의 `Download Boot Success`를 확인한다.
4. `Test Device` 또는 `TestDevice`로 통신 상태를 확인한다.
5. `ReadCapability`에서 `ReadLBA: Enable`을 확인한다. `Disable`이거나 통신 오류가 있으면 중단한다.
6. 원문 백업 절차에 따라 본인 기기의 파티션 정보와 원본 이미지를 읽어 보관한다.

| 백업 확인 | 확인 방법 |
| --- | --- |
| 파티션 정보 | `Name`, `LBA`, `Size`를 텍스트와 캡처로 보관한다. `config_16.cfg`와 `parameter`도 함께 보관한다. |
| 정보 확보 방법 | [SUNMI 24번 글](https://gall.dcinside.com/mgallery/board/view/?id=sunmitechnology&no=24&page=1)의 rkDumper와 `Dev Partition` 절차, [빌더 백업 문서](https://github.com/kyseong00/toss-front-lineageos-builder/blob/main/BACKUP.md)를 참고한다. |
| 파티션 읽기 | 실제 기기에서 확인한 `LBA`를 `Start`, `Size`를 `Count`에 넣고 `ExportImage`로 읽는다. `Size`는 바이트 수가 아니라 LBA 섹터 수다. |
| 파일 보존 | 추출 결과가 같은 이름으로 만들어질 수 있으므로, 다음 추출 전에 파티션 이름으로 변경한다. |
| 파일 검증 | 파일 크기를 확인하고, 내용이 `CC` 같은 값만 반복하는 잘못된 추출인지 점검한다. 성공 로그나 파일 크기만으로 정상 백업을 확정하지 않는다. |
| 복구 준비 | 검증한 이미지와 파티션 기록을 작업 폴더 외의 안전한 위치에도 복사한다. 원본을 빌드 결과로 덮어쓰지 않는다. |

기본 Loader에서는 실제 데이터 대신 `CC`가 반복되는 백업이 나올 수 있다는 사례가 있다. 자세한 추출과 검증은 [SUNMI 25번 글](https://gall.dcinside.com/mgallery/board/view/?id=sunmitechnology&no=25&page=1)을 확인한다. 원본 백업과 파티션 정보를 확보하지 못했다면 다운그레이드를 시작하지 않는다.

## 6. 순정 펌웨어 다운그레이드

성공 사례에서는 다운그레이드 후 초기화 버튼으로 Loader 진입이 가능해졌다. 이미 Loader 진입이 가능한 기기에 다운그레이드가 반드시 필요한지는 이 기록에서 검증하지 않았다.

1. RKDevTool의 `Download Image` 탭에서 목록을 우클릭하고 `Load Config`를 선택한다.
2. 준비할 `config.zip`의 압축을 풀고 `config_16.cfg`를 불러온다.
3. 기록한 본인 기기의 파티션 표와 cfg의 이름, 시작 주소, 크기를 대조한다. 일치하지 않으면 `Run`을 누르지 않는다.
4. 다운그레이드에 필요한 7개 이미지의 체크박스를 선택하고 각 행의 파일 선택란에 해당 이미지를 지정한다. 이름이나 순서를 추측해 끼워 넣지 않는다.
5. 파일 경로와 파티션 대응을 재확인한 뒤 `Run`을 누른다.
6. 완료 로그를 확인한 후 USB-C 전원을 분리한다. 쓰기 도중에는 분리하지 않는다.
7. Micro USB 연결을 유지하고, 초기화 버튼을 누른 채 USB-C 전원을 연결한다.
8. `Found One LOADER Device`가 표시되면 초기화 버튼을 놓는다.

7개 파일의 정확한 목록과 파티션 대응표는 준비 예정이다. 검증된 목록이 없으면 이 단계를 진행하지 않는다.

## 7. LineageOS 이미지 만들기

1. [원본 빌더 GitHub](https://github.com/kyseong00/toss-front-lineageos-builder)에서 `Code` → `Download ZIP`으로 소스를 받는다.
2. 받은 `toss-front-lineageos-builder-main.zip`을 C 드라이브의 작업 폴더에 압축 해제한다.
3. 성공 기록에서는 다운그레이드에 사용한 순정 `super.img`를 `C:\super.img`로 복사했다. 최초 원본 백업은 별도 보관한다. 빌더는 본인 기기에서 백업한 순정 이미지를 요구하므로 출처와 호환성을 확인한다.
4. 압축을 푼 폴더의 `Build.bat`을 실행한다.
5. 입력창에 `C:\super.img`를 입력하거나 파일을 창으로 끌어다 놓고 Enter를 누른다.
6. 완료 메시지를 확인하고 `output` 폴더의 생성 결과를 확인한다.

| 확인 항목 | 내용 |
| --- | --- |
| 생성 파일 | `super_PLF02WH_lineage18.1_gapps_pico.img` 등 빌더가 안내한 결과 파일 |
| 입력 구분 | 순정 `super.img`와 생성된 LineageOS 이미지를 혼동하지 않는다. |
| 빌드 결과 | 오류 없이 완료됐는지 로그를 확인한다. 파일이 생겼다는 이유만으로 성공으로 판단하지 않는다. |
| 버전 기록 | 사용한 빌더 커밋, 입력과 출력의 해시를 함께 기록한다. 기본 브랜치의 내용은 이후 바뀔 수 있다. |

## 8. `super` 파티션 플래싱

1. RKDevTool에서 `LOADER` 인식을 확인한다.
2. `Download Image` 목록을 우클릭하고 `Clear Items`로 기존 다운그레이드 선택을 지운다.
3. `Load Config`로 설정을 다시 불러오고 `Dev Partition`을 누른다.
4. `Do you want to update image download address?`가 뜨면 [SUNMI 24번 글](https://gall.dcinside.com/mgallery/board/view/?id=sunmitechnology&no=24&page=1)의 절차처럼 `아니요`를 선택하고, 파티션 읽기 성공을 확인한다. 다른 경고나 오류는 무시하지 않는다.
5. 오른쪽에 표시된 `Name`, `LBA`, `Size`를 저장한다. 특히 `super`와 `userdata` 행을 남겨 둔다.
6. **`super` 행 하나만 선택한다.** 다른 행의 체크박스가 모두 해제됐는지 확인한다.
7. `super` 행에 7단계에서 만든 LineageOS 이미지를 지정한다.
8. 실제 기기의 `super` 주소와 설정의 쓰기 주소, 이미지의 대상과 크기를 대조한 뒤 `Run`을 누른다.
9. 완료 로그를 확인한 뒤 부팅 상태를 확인한다. 성공 기록에서는 토스 로고 다음에 LineageOS 부팅 화면이 나타났다.

## 9. 부팅이 반복될 때 `userdata` 초기화

성공 사례에서는 기존 사용자 데이터가 남아 부팅 화면이 반복됐고, `userdata`를 지운 뒤 정상 부팅했다. 모든 부팅 실패가 같은 원인은 아니다. 정상 부팅한 기기에서 이 작업을 추가로 할 필요는 없다.

**`EraseLBA`는 입력한 범위를 삭제한다. 잘못된 주소를 넣으면 다른 파티션까지 지워질 수 있다. 삭제된 사용자 데이터는 이 절차로 되돌릴 수 없다.**

1. 플래싱이 완료됐는지 확인한 뒤 전원을 분리한다.
2. 초기화 버튼을 누른 채 USB-C 전원을 다시 연결하고 `LOADER` 인식을 확인한다.
3. 현재 기기에서 `Dev Partition`으로 파티션 정보를 다시 읽어, 8단계에서 저장한 표와 대조한다.
4. `userdata` 행의 `LBA`와 `Size`를 확인한다.
5. `Advanced Function`의 `Start`와 `Count`에 아래와 같이 입력한다.

| 입력란 | 넣을 값 |
| --- | --- |
| `Start` | 본인 기기의 현재 `userdata` 행에 표시된 `LBA` |
| `Count` | 같은 행에 표시된 `Size`. 종료 주소나 바이트 수가 아니다. |

6. 삭제 범위가 `userdata` 안에만 들어가는지, 저장 장치 용량을 넘지 않는지 재확인한다. 진법과 섹터 단위를 유지한다.
7. 필요한 데이터의 백업과 입력값을 검증한 뒤 `EraseLBA`를 누른다.
8. 삭제 완료 로그를 확인한 후 전원을 분리했다가 다시 연결한다.

다른 성공 사례의 주소를 고정값으로 제공하지 않는다. 파티션 표를 읽지 못하거나 범위를 확인할 수 없으면 삭제하지 않는다.
